# Optional LLM narrative enrichment

Deterministic scenario generation never requires an LLM. The pipeline produces a
complete, valid, reproducible scenario from **seed + approved templates** alone —
no API keys, no network, no model calls.

LLM narrative content (from the `llm-narrative-integration` change: organisation
profiles, email chains, memos, CTF narratives, hackerbot dialogue, etc.) is an
**additive enrichment layer**, not a dependency:

- An intent may carry an optional `narrative_generation` block
  (`Intent#llm_options`). It is validated only lightly (provider must be one of
  `ollama`, `openai`, `anthropic`, `llama_cpp`, `lm_studio` when present) and is
  **ignored by deterministic generation**.
- The deterministic path uses only the seed and template content; flag values and
  every generated byte are pure functions of those inputs.
- Narrative content, when used, is layered onto the scenario via the
  `<narrative>` element (see the `llm-narrative-integration` schema extension) and
  the `llm_*` generators. It can be regenerated or omitted without affecting the
  vulnerable software, the flags, or validation.

Recommended usage: generate and validate the deterministic scenario first, then
optionally enrich it with narrative content for engagement. Because narrative
generation is non-deterministic by nature, keep it out of the reproducibility
manifest's hashed artifact set (the manifest hashes only the deterministic
module/scenario/doc outputs).
